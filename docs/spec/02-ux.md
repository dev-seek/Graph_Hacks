## 4. Screens, onboarding, demo and judge mode

### 4.1 Routes (Next.js App Router)
| Route | Purpose |
|---|---|
| `/` | Landing: hero, how it works in 3 steps, "See an example family" (demo), "Start with your story", trust strip, footer attributions |
| `/start` | Consent-lite screen (what we store, that it's not a diagnosis, delete any time, demo deployment deletes after 7 days) → age + story |
| `/j/[id]` | Journey home: current step card, their constellation (findings only), timeline, next step. Token in URL fragment or local storage — see §17 |
| `/j/[id]/confirm` | "Here's what we understood" — each extracted item in plain words with the quote it came from |
| `/j/[id]/round/[n]` | One round of 3–5 questions; each with a "why we ask" line; answers Yes / No / Not sure |
| `/j/[id]/doctor` | See-doctor step: why now (plain), what to bring, "questions to ask your doctor", doctor pack link, upload doctor letter |
| `/j/[id]/pack` | Printable doctor pack (print stylesheet; A4 and Letter) with clinician code + QR to the clinician view |
| `/j/[id]/timeline` | Everything recorded, by date, with source badges |
| `/clinician/[id]` | Clinician view (needs clinician code); "Download Phenopacket (JSON)" |
| `/centre` | Centre brain dashboard |
| `/demo` | Three example families, step-through replay |
| `/about` | How it works, data sources and versions, attributions, limitations, AI-use disclosure, contact |
| `/help` | FAQ, how-it-works diagram, links to the demo and the tour (§4.7) |

### 4.2 Parent screens — content rules
- One main action per screen. Progress shown as "Round 2" and "What happens next", never as a percentage.
- Question card: the question (≤ 20 words), a "why we ask" line (≤ 20 words, no disease names), optional "how to check" tip for things a parent can observe, answer buttons. "Not sure" is always valid and never penalised in copy.
- The constellation: each confirmed finding is a star (Starlight on Night); stars join with lines when findings belong to the same body system. Purely visual; no disease names. Reduced motion → static.
- Doctor step explains *why now* in one of three plain reasons: "the details you've shared fit a pattern worth a doctor's look", "the next useful checks need a doctor", or "you've noticed something that should be seen soon".

### 4.3 Clinician view
Findings table (term, plain label, HPO ID, present/absent, source, onset, date); top 10 candidate patterns with: rank, relative support (bar, no fake precision), the 3 findings that support it most, the findings that argue against it, explanation path (finding → HPO ancestor → disease annotation) rendered from FalkorDB; suggested checks (test-observable terms with highest information gain); referral letter draft (editable, copy/print); GA4GH Phenopacket v2 JSON export (validated against the schema; includes present and excluded HPO terms with onset, sex if given, and a metaData block naming HPO version). Banner: clinician disclaimer (§6.5).

### 4.4 Onboarding for a first-time visitor (must work in under 10 seconds)
Landing hero says who it's for and what it does; the first secondary button is "See an example family (2 min)". `/demo` opens with a 3-card picker. Each demo step has a short caption ("Here Kabir's mum describes the last two years…"). A persistent banner on demo pages: "Example family — all details are made up."

### 4.5 Demo journeys (synthetic, built from the dev split; recorded once, replayed with cached LLM outputs)
1. **"Kabir, 3"** — a dev-split case with a strong multi-system neurodevelopmental phenotype (Angelman-like if such a case is in the dev split) → story → 2 home rounds → see doctor → synthetic doctor letter adds exam/test findings → referral ready → "6 months later" watch check.
2. **"Arjun, 6"** — a synthetic *common-explanation* vignette (e.g., mild isolated speech delay with normal everything else) → one round → **no escalation**: "see your doctor at the next routine visit; here's what to watch". Shows restraint.
3. **"Maya, 7"** — story mentions a seizure happening for more than 5 minutes → urgent screen immediately (red-flag stop).
The three demo stories and two sample doctor letters come from `review/demo_stories.md` and `review/doctor_letters.md` (drafted by Claude, reviewed by the human). The agent picks dev-split cases that match each story by the criteria stated there.
Each demo also has a **clinician view** and the judge panel.

### 4.6 Judge mode — live FalkorDB inspector
Toggle (top right on demo pages, `?judge=1`; split screen on desktop). Side panel shows, for each step: the named graph queries that ran (from the query registry) with timings, node/edge counts touched, gate decision with the numbers behind it, a live mini-graph of the family evidence graph (cytoscape.js), and a link to open the same graph in FalkorDB Browser (local setup). This is how judges see that FalkorDB does the real work.

### 4.7 Guided tour, examples and help (anyone must be able to use it without instructions)
- **Welcome tour (first visit, every role):** 4 short steps for parents — what Constellation is and isn't (not a diagnosis); how a round works (3–5 questions, "Not sure" is fine); what the doctor pack is; privacy and delete. 3 steps for clinicians (findings with sources → candidates with graph paths → referral + Phenopacket). 3 steps for the centre (look-alikes and who solved them → bridge signs and clusters → knowledge-update re-check). Buttons: Next, Back, Skip. Reopen any time from "How it works" in the header. Keyboard operable, focus-trapped, screen-reader labelled, respects reduced motion; "seen" stored in localStorage inside try/catch (works without it).
- **Try with an example:** `/start` offers "Use an example story" which pre-fills a made-up story (clearly labelled) so a new visitor reaches the first question round in two clicks without typing.
- **Example families:** `/demo` shows Kabir, Arjun and Maya as cards with one-line outcomes; each step has a caption ("Here the agent asks about sleep because it best separates the remaining patterns") and the live inspector toggle.
- **Contextual help:** every question has "Why we ask"; the doctor step explains "What is a doctor pack?"; the clinician view explains "How this ranking works" (likelihood ratios in plain words) and "What is a Phenopacket?".
- **`/help`:** 12 plain-language FAQs (Is this a diagnosis? What happens to my data? Why "Not sure"? What does the doctor get? Can I delete everything? …), a 1-minute "how it works" diagram, and links to the demo.
- **Empty and error states** always say what happened and the next step (never a blank screen or a stack trace).
