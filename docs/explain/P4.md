# P4 in plain English: the web app

**What was built.** A calm website a worried parent can use in ten seconds: a landing page, a short "story" form, a "here's what we understood" check, rounds of three to five questions with Yes / No / Not sure, a see-a-doctor step with a printable one-page pack (A4 and Letter, with a QR code that opens the clinician view), a timeline, and a delete button. Stars appear in a small sky picture as the parent confirms things. Doctors get a separate view with findings and their sources, candidate patterns with the graph path behind each, suggested checks, an editable referral letter and a Phenopacket download. `/demo` plays Kabir, Arjun and Maya step by step; switching on the FalkorDB inspector shows, for every step, the named graph queries with their Cypher, row counts and timings, the numbers behind the gate decision, and a small graph of the evidence. There is a first-visit tour for parents (4 steps), clinicians (3) and the centre (3), a help page with 12 questions, and an About page with the exact data attributions, limits and AI disclosure.

**How it is kept safe.** Parent screens never show disease names, scores or ranks. Tests check this three ways: the code that builds the pages, the recorded demo text against all 19,652 disease names read out of FalkorDB, and the real page text in a browser. Urgent stories stop on a red, icon-marked screen with the mandatory text.

**Numbers.** 41 unit tests, 21 browser tests (axe WCAG 2.2 AA clean, keyboard-only journey and tour, 360 px no sideways scroll). Lighthouse accessibility: 100 on `/`, `/demo` and a question round (gate: ≥ 95). Screenshots at 360 and 1280 px and the two print PDFs are in `docs/explain/P4-screens/`.

**Things worth knowing.**
- With no Claude key the story reader only splits sentences, so a long free-text story often ends in "keep watching" with no rounds. The "Use an example story" button therefore uses a short list of plain phrases; with a key this should be better, but that is unmeasured.
- Disease names that are also sign names (for example "Cleft palate") are allowed in parent text because a sign is not a diagnosis (ADR-0012).
- The clinician disclaimer shown is the spec's mandatory §6.5 text; the API's own disclaimer field still has older wording (frozen contract).
- The centre page is an honest "not switched on yet" screen until P5.
- A bug found on the way: `LLM_MODE=off` crashed the API because YAML reads unquoted `off` as false. Fixed with a test.
