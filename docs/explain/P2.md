# P2 in plain English: the engine, the gates and safety

**What this phase built.** The part that decides, with plain code and no language model: which diseases are still plausible, which small question to ask next, when to say "see a doctor", and when a parent message is an emergency.

- **Scoring** (`engine/scoring.py`). Each sign the parent reports, or rules out, raises or lowers each disease by a fixed rule (how common the sign is in that disease, how common it is everywhere, broader or narrower matches, "this disease never has this sign"). It always runs on rows the graph database returns.
- **Graph-first rounds.** Every round asks FalkorDB (Cypher queries in the registry: prune redundant signs, retrieve candidates, fetch planner inputs). If the graph is down the service says "unavailable" (503); it never guesses.
- **Planner and gates** (`engine/planner.py`, `gates.py`). Picks at most a few easy questions a round (age-appropriate, not repeating, at most two per body system) and moves a family through "keep watching", "mention at routine visit", "see a doctor" or "referral ready" using thresholds 0.30 / 0.40 / 0.50.
- **Safety engine** (`safety/`). Red-flag rules in `review/safety_rules.yaml` (reviewed by the human) run first on every message. It passes its own 60-item test corpus 60/60. A language model may only add a flag, never remove one.
- **Simulator and evaluation.** A simulated parent answers from a real case; three baselines (story only, random questions, most-frequent questions) are compared with bootstrap confidence intervals. 40 reviewed "ordinary child" vignettes check for false alarms.
- **Speed.** Per round, 90th percentile: retrieve 80 ms, score 31 ms, plan 98 ms (budgets 300 / 100 / 500).
- **API contract frozen** (`api/schemas.py`, OpenAPI exported). A test walks every parent response and fails if a disease name or probability appears.

**Honest result.** On 400 held-out dev cases our top-10 rate (60.2%) beats story-only (56.2%) but is level with the "ask the most frequent questions" baseline (60.5%); our MRR is 0.369 vs 0.368. The gate "beats all three baselines" was **not met**. The human decided to report it as is (ADR-0007); nothing was re-tuned toward the baseline.
False alarms on the 40 ordinary-child vignettes: 0% referrals, 20% "see a doctor" (limits 10% / 30%), and the safety rules alone sent none. Cost: only about 21% of true cases reach a referral and 25% end at "mention at routine visit".

**Things worth knowing.**
- Spec Q2 queries were rewritten to be about 100x faster with identical rows (ADR-0008, equivalence test).
- FalkorDB 6.0.2 returns 0 rows for `UNWIND` plus a downward variable-length match; minimal repro in `docs/VERIFIED.md`. Still present on the newest edge build, absent on v4.22.1. Worth reporting upstream.
- The guard hook once treated the template line "change this line to REVIEWED by" as a real approval; fixed and tested (task 12).
- Next phase (P3) wires this engine into agents and the API: question phrasing checks must ban disease-flavoured words.
