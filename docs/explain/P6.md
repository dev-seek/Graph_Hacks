# P6 in plain English: hardening, deployment files, README and submission drafts

**What was built.** The pieces that make the project shippable. (1) A *daily token budget* for the language model: once it is used up, the app quietly falls back to the plain-code readers, so a public demo cannot run up a bill. (2) A *7-day cleanup job* that erases family graphs older than a week (only `family_*` graphs; the knowledge, clinic and checkpoint graphs are never touched). (3) A size cap on uploaded PDFs, checked before decoding. (4) A production setup: Caddy in front (security headers, HTTPS when a real domain is given, 8 MB request cap), the web app and API on a private network, FalkorDB not reachable from outside, and a one-command "seed" step that builds the graphs. (5) A complete README, a 5-minute user guide, a video script, a blog outline, a deploy guide and a submission checklist.

**How it was checked.** The production stack ran locally on a fresh FalkorDB volume: security headers present, the 11th "new family" request from one visitor refused (429), a faked `X-Forwarded-For` ignored, and all 29 browser tests passing through Caddy with the strict content-security policy. A fresh `git clone` followed only the README commands in a separate compose project: about 3.3 minutes, then `make check` and 77 integration tests green. `pip-audit` and `pnpm audit` report nothing; gitleaks over 92 commits finds no secrets; CI now fails on audit findings.

**Things worth knowing.**
- Nothing is deployed yet: no `DEPLOY_HOST`/`DEPLOY_DOMAIN` was provided. `docs/submission/deploy.md` has the exact commands; what was and was not verified is spelled out there.
- The fresh-clone test found real snags that are now fixed: the API container did not have the `review/` folder (so the safety rules were missing), nor the demo recordings; the dev compose still had a stub web service; there was no single `make seed`.
- After any FalkorDB restart, run the seed step again (it can lose recent graphs and change term search; see `docs/VERIFIED.md`).
- The `/demo` pages replay queries recorded when each example family was run, and say so. The live inspector (never-cut) was wired in this phase: "Use an example story" now creates an example family whose journey page has a *FalkorDB inspector (live)* link (ADR-0016).
- The README says plainly that the system does not beat the "most frequent questions" baseline, and that the cost per journey and the Claude profiles were never measured (no key).
- Left for the human: the live URL, the video, the blog post, the demo GIF, team and tagline (see `docs/submission/checklist.md`).
