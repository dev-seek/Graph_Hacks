# P3 in plain English: agents, API, family memory, demos

**What this phase built.** Everything that turns the engine into a working product behind an API.

- **Language-model layer** (`backend/app/llm/`). One small interface, five modes: `off` (no model, deterministic fallbacks), `fake` (tests), `replay` (recorded answers, no key), `record`, `live`. Every call has a time limit, a one-repair retry, a per-family budget and a fallback, and never logs a parent's words. The code that talks to Claude lives in one file. **Not measured:** no API key was set, so which Claude profile is cheapest was never tested (ADR-0009); the request shape was only checked against a stub server.
- **Family memory** (`graph/family.py`). Each family gets its own FalkorDB graph: findings with the sentence they came from, corrections that keep history, rounds, questions and answers, snapshots, gates, flags and artifacts. Deleting a family removes the graph and its saved agent state.
- **The agent** (`agents/`). A LangGraph state machine whose only waiting point is a single "await event" node, so resuming (even in another process) never repeats model calls or writes. It runs safety first, reads the story, resolves words to medical terms through the graph, scores, applies the gates, plans questions, builds the doctor pack, drafts a referral letter and exports a GA4GH Phenopacket (validated with the official schema).
- **API** (`api/`). Parent routes need a bearer token (stored hashed); clinician routes need a short code. Unknown family and wrong token look the same (401). Every route is tested for this, and parent answers are scanned for condition language.
- **MCP server** (`mcp/`): four read-only tools (resolve phenotype, rank candidates, explain candidate, centre routing; the last answers "not available" until P5).
- **Demos.** Kabir (referral ready), Arjun (nothing needed), Maya (emergency stop) are recorded to `data/demo/` and `make demo-replay` reproduces all three offline.

**Be honest about the demos.** No LLM key existed, so they were recorded in `off` mode: the parent's reading of the story used the rules-only fallback, and "the parent confirms the list" was simulated by keeping list items related to the matched dev-split case (ground truth), as the answers to questions are. Kabir's matched case is `PMID_40215970_F11_II_2` (22 signs, overlap 0.31). Question wording is still the rules-only P1 copy ("Have you noticed Long nose in your child?"), which a language-model pass or the copy reviewer should improve in P4.

**What the reviewer-style check changed.** Safety rules now run before any model call (a test proves Maya's story never reaches a model). Parents are only asked questions that pass a wording check and have a lay synonym (ADR-0011).

**Things worth knowing.** Referral still only happens for about one in five true cases (P2). Health-check wording like "abnormality" is banned from parent text. The daily watcher is a switch (`WATCHER_INTERVAL_S`), off by default.
